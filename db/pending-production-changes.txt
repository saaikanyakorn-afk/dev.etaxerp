SECTION 1: SCHEMA CHANGES (ALTER TABLE)
--------------------------------------------------------

3 new columns added to the `expenses` table.
All use IF NOT EXISTS — safe to run even if already present.
All have DEFAULT values — no existing rows will be affected.

-- 1a. Store the original foreign currency code (e.g. USD, EUR)
ALTER TABLE expenses
  ADD COLUMN IF NOT EXISTS currency_code TEXT NOT NULL DEFAULT 'THB';

-- 1b. Store the exchange rate used (THB per 1 unit of foreign currency)
ALTER TABLE expenses
  ADD COLUMN IF NOT EXISTS exchange_rate DECIMAL(15,6) NOT NULL DEFAULT 1;

-- 1c. Store how much of the AP balance has been paid (for outstanding display)
ALTER TABLE expenses
  ADD COLUMN IF NOT EXISTS paid_amount DECIMAL(15,2) NOT NULL DEFAULT 0;

WHY:
- currency_code / exchange_rate: expenses can now be entered in USD/EUR/etc.
  The app stores totalAmount in THB (rate × foreign amount) and keeps the
  original foreign values here for display and reference.
- paid_amount: used to calculate outstanding balance for credit (AP) expenses.
  Default 0 means all existing expenses show full amount as outstanding
  until manually updated or paid via payment voucher.

RISK: Very low. All three are additive columns with safe defaults.
      No existing data is altered. IF NOT EXISTS prevents errors on re-run.
